### 1.1 Lean profile

- Did: wrote `debloat/openclaw.lean.json5`. It is generated by `scripts/debloat/apply.mjs`
  (`--lean-config-only`) so the deny list always equals "every plugin still in the tree
  minus the keep set"; after each removal it shrinks and never names a deleted plugin.
  Keys used (all present in `src/config/zod-schema.*` and docs): `plugins.allow` (anthropic,
  telegram, browser, duckduckgo, web-readability, memory-core), `plugins.deny` (159 others),
  `plugins.slots.memory`, `plugins.entries.*.enabled`, `tools.sessions.visibility: "tree"`,
  `tools.agentToAgent.enabled: false`, `tools.web.search.provider: "duckduckgo"`,
  `update.checkOnStart: false`, `telemetry.enabled: false`, `discovery.mdns.mode: "off"`,
  `gateway.auth.mode: "token"` (token from `OPENCLAW_GATEWAY_TOKEN`),
  `browser.extensionRelay.allowLegacyAuth: false`, `memory.search.provider: "none"`
  (keyword recall; Anthropic has no embeddings API), `memory.search.rememberAcrossConversations:
false` (needs the denied Active Memory plugin), `skills.allowBundled` (7 usable skills).
  Not used: `agents.defaults.experimental.localModelLean` (drops browser and cron).
- Choices: DuckDuckGo is the kept web search provider because it is key-free (it never wins
  auto-detection, so the profile selects it explicitly). Web fetch uses the core tool plus
  `web-readability`.
- Validation: `openclaw config validate` passes on an isolated instance; a Gateway booted with
  the profile (own HOME/state/config, port 29789) loaded exactly anthropic, browser, duckduckgo,
  memory-core, telegram; `doctor --non-interactive` reports no errors. Its only channel warning
  is the expected Telegram 401 from the placeholder token. Every doctor finding that a config
  key could settle (memory provider, Active Memory recall, relay legacy auth, gateway auth,
  auto-enabled entries) is now set in the profile.
